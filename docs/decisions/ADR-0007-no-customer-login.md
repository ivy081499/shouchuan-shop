# ADR-0007 前台訪客結帳，不做客戶登入

**狀態**：已採用
**日期**：2026-09-11

## 背景

店主詢問客戶登入要用 Google 還是 LINE，以及是否需要費用。

兩者確實都免費（LINE Login 免費，收費的是 Messaging API 的推播訊息，屬不同服務）。
但問題不在成本，而在**是否需要**。

## 決策

**前台不做客戶登入，採訪客結帳。**

客戶在本站只需要做兩件事：
1. 下單
2. 回報轉帳末五碼

兩件都能用「訂單編號 + 手機末三碼」完成（見 `src/contracts/order.ts` 的 `orderLookupSchema`），
不需要帳號。

**後台**則用 Cloudflare Access（Google 帳號驗證），不自建帳密系統。

## 後果

**好處**
- 零客戶階段，每一道「請先登入」都會流失買家；訪客結帳轉換率最高
- 不必保管客戶密碼，沒有個資外洩的額外責任
- 少一整套帳號管理、忘記密碼、重設信流程要寫與維護

**代價**
- 客戶看不到「我的訂單」歷史清單，只能一筆一筆用訂單編號查
- 無法做會員回購、累積消費、生日優惠這類功能

**日後要加登入時**
訂單已存手機號碼，可以用手機號碼把歷史訂單關聯到新建立的帳號，不會遺失資料。
等真的有回購客戶、確定值得做會員制時再加，屆時成本也不高。

## 為什麼後台也不自建登入

| | 自建帳密 | Cloudflare Access |
|---|---|---|
| 誰擋下未授權者 | 應用程式自己 | Cloudflare 邊緣，請求進不到網站 |
| 密碼風險 | 要自做雜湊、session、防暴力破解 | 沒有密碼可外洩 |
| 成本 | 要寫、要維護 | 免費 50 席 |

店主只有一人使用後台，自建帳密是純粹多餘的工作，且做差了就是資安漏洞。
另有伺服器端複查 `Cf-Access-Authenticated-User-Email` 作為第二層防護。
