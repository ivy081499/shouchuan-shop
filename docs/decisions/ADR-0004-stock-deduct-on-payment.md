# ADR-0004 付款確認才扣庫存（接受超賣風險）

**狀態**：已採用
**日期**：2026-09-11

## 背景

庫存扣減時機有兩種選擇：

| 方案 | 優點 | 缺點 |
|---|---|---|
| 下單即預扣 | 杜絕超賣 | 需要逾時釋放機制（排程），未付款的訂單會卡住庫存 |
| 付款確認才扣 | 簡單，不卡庫存 | **可能超賣** |

店主明確選擇「付款才實扣」。

## 決策

庫存只在訂單轉入 `paid` 狀態時扣減。

為了讓超賣可控，加上兩個機制：
1. 下單時把「當下可售數量」記入 `order_items.availableAtOrderTime`
2. 後台訂單列表即時計算庫存是否仍足夠，不足者**標紅警示**

## 後果

**好處**
- 不需要排程任務（Cloudflare 免費版的 Cron Trigger 有限制）
- 未付款訂單不會佔住庫存

**代價**
- 兩位客戶同時下單同一款、材料只夠一條時，兩張訂單都會成立
- 店主必須在出貨前看警示，自行決定補料或退款

**已告知店主並獲同意。** 不要自行改成預扣方案。

**實作要求**
- `stockDeducted` 旗標保證冪等，不可重複扣
- 訂單取消且已扣庫存 → 必須加回並寫 `stock_ledger`
