# ADR-0011 關稅攤提與進貨隔離流程

**狀態**：已採用
**日期**：2026-09-16

## 背景

店主的進貨成本除了貨款與運費，還有**關稅**。關稅是「一批貨清關一次」收的，
不是每張淘寶訂單各收一次——6 張訂單集運併單，海關只收一筆。

原本的 `purchases` 是「一張淘寶訂單 = 一張進貨單」，沒有「一批貨」這一層，
關稅無處可掛。

## 決策

### 1. 新增 `shipments` 表（到貨批次）

一批貨 = 一次清關 = 一筆關稅。`purchases.shipment_id` 指向所屬批次。
`purchase_items.duty_share_twd_cents` 記錄各列攤得的關稅。

### 2. 關稅按「台幣到岸價」比例攤提

```
單顆成本 = (貨款 + 攤得運費) × 匯率 + 攤得關稅 ÷ 總顆數
```

兩層攤提，順序不可對調：
1. **運費**：各張淘寶訂單內部，按該單各列貨款比例攤
2. **關稅**：整批跨訂單，按各列「含運費的台幣金額」比例攤

**關稅基準是台幣不是人民幣**。海關收台幣，且不同訂單可能有不同匯率，
用人民幣當基準會讓比例失真。

實作在 `src/lib/costing.ts` 的 `calcShipmentCosts()`，
**不要改 `calcPurchaseCosts()`** —— 那是單張訂單用的，算不了跨訂單的關稅。

### 3. 【硬規則】進貨一律隔離處理

店主明確要求：**以後每次進貨都要另開分支，資料庫也要分開，完全不能影響現行資料。**

```bash
# 開工
git worktree add .claude/worktrees/<批次名> -b <批次名>
cd .claude/worktrees/<批次名>
npm install
mkdir -p .data && cp ../../../.data/local.sqlite .data/local.sqlite   # 複製一份來改

# 驗證無誤、店主確認後才合併回 main
```

現行資料庫在 `~/Desktop/手串/.data/local.sqlite`，**進貨作業絕不可直接寫它**。

## 後果

**好處**
- 關稅算錯不會污染現行成本資料，改壞了丟掉 worktree 即可
- 每批貨的關稅有獨立紀錄，日後查帳看得出哪批繳了多少
- 分批攤提，不同批次的關稅率不同也能正確反映

**代價**
- 每次進貨多兩個步驟（開 worktree、複製 DB）
- 合併前要記得把 DB 變更同步回現行資料庫（不是 git 管的，要手動）

## 2026-10-26 全量核對

店主要求拿淘寶原始清單全量核對兩批進貨。核對 `進貨紀錄` 試算表
（解析-01 共 51 筆、解析-02 共 23 筆）對照系統 `purchase_items`。

**結果：成本正確。** 兩批的品項筆數、人民幣金額、件數全部一致，
系統關稅攤提加總 = NT$803 無誤。

**釐清一件事**：試算表「單顆成本NT$」欄的公式是
`(金額×件數＋攤得運費)×匯率÷總顆數`，**刻意不含關稅**——
試算表只記原始貨款，均攤是系統的職責（見本文件「決策」章節）。
曾有一次誤判為「試算表漏算關稅」而打算回寫，已停手。
**以後核對時不要把這個差異當成錯誤。**

**修正的項目**：解析-02 第 22 列「包珠圈 8mm 鋼色」訂單號誤植為
`5127801481240456940`，正確為 `5127801481240467013`（以原始-02 為準）。
試算表與 `purchases.id=16` 皆已更正，金額、運費、成本不受影響。
