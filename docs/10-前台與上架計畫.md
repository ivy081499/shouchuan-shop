# 前台自建與上架補完 — 實作計畫

**決策依據**：`docs/decisions/ADR-0012`
**建立日期**：2026-09-22
**狀態**：規劃完成，**尚未開始實作**

---

## 一句話目標

讓店主能在後台完整上架一條手串，客人能在自己的網站上看到它、買下它，
下單後收到確認信，並可自由選擇要不要用 Google 註冊成會員。

---

## 為什麼要分四個階段

每個階段結束都能**單獨驗收、單獨上線**，不必等全部做完才看得到東西。
順序不可調換，理由寫在各階段。

| 階段 | 做什麼 | 結束時可以驗收什麼 | 需要 schema？ |
|---|---|---|---|
| **A** | 後台上架補完 | 一條手串的所有欄位都填得了 | 否 |
| **B** | 前台看商品 | 客人看得到商品頁（還不能買） | 否 |
| **C** | 購物車與結帳 | 客人買得到、你收得到訂單與信 | 否 |
| **D** | 會員（Google 登入） | 客人可註冊、查自己的訂單 | **是** |

**A 必須最先做**：前台顯示什麼取決於後台填得了什麼。沒有商品故事、沒有手圍，
前台做出來也是空的。

**D 放最後**：會員是「加分」不是「必要」。訪客下單（C）自己就能成立，
會員晚一週上線不影響開賣。而且 D 要改 schema，隔離開來比較安全。

## 階段 A：後台上架補完

**目標**：`products` 表的每個欄位，店主都改得到。

### A-1 商品編輯器補齊欄位

目前 `RecipeEditor.tsx` 的「基本資料」卡只有名稱、售價、狀態。要補：

| 欄位 | 介面 | 注意事項 |
|---|---|---|
| `description` | 多行文字框 | 商品故事，前台會顯示。支援換行 |
| `wristSizeCm` | 數字輸入 | 手圍公分，可留空 |
| `manualStock` | 數字輸入 + 「依配方自動計算」勾選 | **留空(null) = 依配方庫存動態算**，填數字 = 手動限量。這個分別要在畫面上講清楚 |
| `sortOrder` | 數字輸入 | 數字越小越前面 |

`productInputSchema` 已經涵蓋全部欄位，**contracts 不用改**。

### A-2 網址代稱（slug）可修改

目前建立後就改不了。要能改，但要處理：

- **唯一性**：重複時要明確報錯（現有 `createProductAction` 已有這段可參考）
- **格式**：只允許小寫英數與連字號（`slugSchema` 已有規範）
- **警告**：若商品已上架，改 slug 會讓舊網址失效。畫面上要提醒

### A-3 商品列表顯示完整度

列表加一欄「資料完整度」，標示哪些商品還缺東西（沒照片／沒故事／沒配方），
店主一眼看出哪些還不能上架。

### A-4 上架前檢查

`status` 要改成「已上架」時，若缺少必要資料就擋下並說明：

| 檢查項 | 缺少時的訊息 |
|---|---|
| 至少一張照片 | 「還沒有照片，客人看不到商品長怎樣」 |
| 有配方 | 「還沒設定用哪些珠子，算不出成本」 |
| 售價 > 0 | 「售價還沒填」 |

**驗收**：建立一條新手串，把所有欄位填完、上架，過程中不需要碰資料庫。

## 階段 B：前台看商品

**目標**：客人能瀏覽商品，但還不能買。

### B-1 前台外殼

- `src/app/(store)/layout.tsx` — 與後台分開的版面
- 店名、簡單導覽、頁尾（匯款資訊、聯絡方式）
- **繁體中文**，不得出現簡體字（`docs/00-PRODUCT.md` 硬規則）
- 遵循 `docs/05-DESIGN-SYSTEM.md`，含禁用清單

### B-2 商品列表頁 `/`

- 只顯示 `status = 'active'` 的商品
- 顯示：主圖、名稱、售價、是否售完
- 依 `sort_order` 排序
- 資料層 `listStoreProducts()` **已經寫好可用**

### B-3 商品詳情頁 `/p/[slug]`

- 多張照片（可切換）
- 商品故事（`description`）
- 手圍、售價
- **配方透視**：這條手串用了哪些珠 —— FreeStore 做不到的差異化
- 可售數量（`getAvailableQty()` 已寫好）
- 資料層 `getProductDetail()` **已經寫好可用**

### B-4 圖片最佳化

`docs/03-ARCHITECTURE.md` 的額度守則：

- 上傳時壓為 webp、長邊上限 1600px（**目前的上傳功能沒做壓縮，要補**）
- 圖片走 R2 公開網址直出，不經 Worker 轉發

**驗收**：用手機開商品頁，照片、故事、配方都看得到，載入不卡。

## 階段 C：購物車與結帳（第一版核心）

**目標**：客人買得到，你收得到訂單與 Email。

### C-1 購物車

- 型別 `cartSchema`、`CART_COOKIE_NAME` **已存在可用**
- 存在 cookie，不需要登入
- 加入、移除、改數量
- **即時檢查可售數量**，超過就擋下

### C-2 結帳頁

**不強迫註冊**。表單欄位：姓名、電話、Email、收件地址、備註。
`checkoutSchema` **已存在可用**。

送出後：

1. 再次檢查庫存（避免同時有人下單）
2. 建立 `orders`（狀態 `pending_payment`）與 `order_items`
3. **寫入成本快照** `unit_cost_cents` —— 這是日後查毛利的依據，不可省略
4. 清空購物車 cookie
5. 寄訂單確認信
6. 轉到成功頁

**此時不扣庫存。** 扣庫存在店主確認收款時發生（`confirmPaymentAndDeductStock()`），
這個不變量不能破壞。

### C-3 訂單確認信

寄給客戶，內容：

- 訂單編號
- 買了什麼、幾條、多少錢
- **匯款帳號**（從 `settings` 表讀，不要寫死）
- 提醒：匯款後請回報末五碼

**技術限制**：Cloudflare Workers 沒有 SMTP，要用 HTTP API 寄信（見 ADR-0012）。
寄信失敗**不可以讓下單失敗**——訂單要先存好，寄信失敗只記錄，店主仍看得到訂單。

### C-4 下單成功頁

- 顯示訂單編號與匯款資訊
- **會員邀請放在這裡**：「要不要用 Google 登入，下次不用重填資料？」
  - 這是階段 D 的入口，D 未完成前先不顯示

### C-5 轉帳回報

客人匯款後回報末五碼。`reportTransfer()` **已經寫好可用**。

**驗收**：用手機完整買一次，收到信，後台看得到訂單，確認收款後庫存正確扣減。

## 階段 D：會員（Google 登入）

**目標**：客人可選擇註冊，之後不用重填資料，並能查自己的訂單。

### D-1 schema 變更（**需要另開 schema session**）

```
customers 表
  id, google_sub（Google 的使用者唯一 id）, email,
  name, picture_url, created_at, updated_at

orders 增 customer_id（可為 null，null = 訪客下單）
```

**已登記在 BOARD，尚未執行。**

### D-2 Google 登入

- 一律 Google，**不自建密碼**（沒有密碼就沒有密碼外洩風險）
- 流程：Google 授權 → 驗證 id_token → 找或建 `customers` → 發 session cookie
- Session 用 HttpOnly + Secure cookie

### D-3 訂單歸戶

註冊當下，把**同一個 Email 的既有訂單**掛到這個會員身上，
客人一登入就看得到過去的訂單，不必客服處理。

### D-4 會員頁 `/me`

- 我的訂單列表與狀態
- 結帳時自動帶入上次的收件資料

**驗收**：用 Google 註冊，看得到剛才訪客身分下的那筆訂單。

## 明確不做（第一版）

| 項目 | 原因 |
|---|---|
| 電子發票 | 要串財政部，流程長。先用手開或不開 |
| 超商取貨 | 要跟物流商簽約。先只做宅配 |
| 刷卡金流 | 要商店審核、有手續費。維持轉帳 |
| 密碼註冊 | 只用 Google，避免密碼安全責任 |
| 優惠券／促銷 | 還沒有客戶，先不做 |
| 商品評價 | 同上 |

這些不是「不好」，是**現在做了也沒用**。有客戶之後再依實際需求加。

## 風險與對策

| 風險 | 對策 |
|---|---|
| **超賣**：兩人同時買最後一條 | 結帳時重新檢查可售量；確認收款扣庫存時再檢查一次（`confirmPaymentAndDeductStock` 已有防呆） |
| **寄信失敗導致下單失敗** | 訂單先寫入資料庫，寄信失敗只記錄不擋流程 |
| **前台是公開的** | Cloudflare Access 只保護 `/admin`；前台所有寫入都要驗證輸入（zod 已有 schema） |
| **免費額度爆掉** | 圖片走 R2 直出、列表頁避免 N+1 查詢（`docs/03-ARCHITECTURE.md` 守則） |
| **FreeStore 並行期商品不同步** | 以自建站為主，FreeStore 只保留既有商品不再新增 |
| **改 schema 污染 D1** | 階段 D 另開 schema session，且不與其他工作流同時進行 |
