## 🔐 密碼放哪裡

**密碼不進這個 repo。** 這裡是 git 版控的，密碼寫進來就會永遠留在提交歷史裡，
即使日後刪除，`git log` 與 GitHub 上的舊版本仍查得到。這是公開商店後台的登入憑證，
被取得就能改商品、看客戶訂單與個資、動金流設定。

**請店主把密碼存在**：瀏覽器密碼管理員、iCloud 鑰匙圈，或 1Password 之類的工具。

### ⚠️ 目前的密碼強度不足

現行帳密為 `admin` + 6 位純數字。這組合有兩個問題：

1. `admin` 是攻擊者第一個嘗試的帳號名
2. 6 位純數字只有 100 萬種組合，自動化工具很快就能試完

**建議店主儘快改為 12 字以上、含大小寫字母與符號的密碼**，並存進密碼管理員。
若 FreeStore 支援兩步驟驗證（2FA），一併開啟。

## 費用結構

- 0 元開店、免月費年費、不綁約
- **成交才收約 1% 成交費**（沒有訂單就不收費）
- 金流、物流、電子發票三項服務各自獨立，**不強制串接**
- 電子發票第一年免系統設定費（第二年起可能收系統服務費，待確認）

## 收款方式

店主採**轉帳收款**，不串付費金流：
- FreeStore 有內建「轉帳通知單」，客戶轉帳後自行回報
- 通知單入口在：網站頁尾、訂單確認信、會員訂單紀錄
- 店主在 FreeStore 後台核對入帳後出貨

## 本系統與 FreeStore 的分工

```
FreeStore（前台）              本系統（後台）
─────────────────             ────────────────
商品展示                       散珠成本管理
購物車、下單                    手串配方（用哪些珠各幾顆）
收轉帳通知                      淘寶進貨匯入（含運費攤提）
出貨、物流                      採購需求報表（依店鋪分組）
會員、電子發票                  毛利報表、庫存報表
```

**資料流**：FreeStore 的訂單 → 匯出 → 匯入本系統 → 才能算採購需求與毛利。

## ⚠️ FreeStore 有頁面快取，驗證不能只看前台

改完設定後前台常常還是舊的（店名、logo、商品都遇過）。
**正確的驗證方式**：從伺服器重新抓取後台頁面，檢查表單欄位的實際值。

```js
const r = await fetch(adminUrl, {credentials:'same-origin'});
const doc = new DOMParser().parseFromString(await r.text(), 'text/html');
doc.querySelector('[name="config_name"]').value   // 這才是真的
```

加 `?nocache=` 參數**無效**，那是伺服器端快取。

## 免費方案的商品上限

**免費方案最多上架 5 項商品。** 後台顯示為「上架商品 (8 / 5)」。

FreeStore 提供解鎖方式：**加入 LINE 官方帳號並提供商店網址，即可解鎖無限上架**（免費）。
店主要上架超過 5 條手串時需自行辦理。

## 商品資料要維護兩份

FreeStore 沒有公開 API，所以：
- **FreeStore**：商品名稱、售價、圖片、庫存數量（給客戶看的）
- **本系統**：同一個商品的配方與成本（給店主算帳用的）

兩邊的商品要對得起來。建議在本系統的 `products.slug` 使用與 FreeStore 相同的商品代稱，
方便日後比對。
